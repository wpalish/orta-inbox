# OrtaInbox

Ручная очередь обращений с независимым одобрением конкретной версии ответа. Оригинальная ограниченная версия 0.1 по референсу Crisp №3.

## Рабочий процесс

1. Администратор создаёт филиал и отдельные аккаунты автора/проверяющего. Координатор вручную регистрирует разрешённый текст обращения и выбирает существующий ответственный аккаунт.
2. Назначенный автор сохраняет черновик и отдельным действием передаёт его на проверку.
3. Другой администратор читает текущую версию и одобряет её. Автор не может одобрить себя. Старая форма не перезаписывает свежий текст и не одобряет невиденную версию.
4. Изменение текста сохраняется черновиком, увеличивает версию и снимает одобрение. Прежние проверки остаются с точными текстом, версией, проверяющим и временем.
5. После нового одобрения автор указывает основание и вручную отмечает отправку. Снимок текста/версии/основания защищён; приложение ничего не отправляет и не проверяет доставку.

У обращения может быть один незавершённый неархивный ответ. Администратор может явно архивировать незавершённый ответ, сохранив его историю. Исходный номер, филиал, тема и вопрос защищены после появления любого ответа, включая архивный. Ответственного можно сменить, когда нет незавершённого неархивного ответа. Закрытие требует завершения или явного архива незавершённых ответов. Новая работа по архивному филиалу или закрытому/архивному обращению отклоняется; старая история читается.

## Запуск

Нужен Node.js >=24.15 <25 со встроенным SQLite. Внешних npm-зависимостей нет.

Задайте `WORK_ADMIN_PASSWORD` длиной 14–200 символов, не добавляя его в Git. `WORK_ADMIN_USER` по умолчанию `admin`. Выполните `npm start`, затем откройте http://127.0.0.1:8792. `PORT`, `PUBLIC_ORIGIN`, `HOST`, `DATABASE_PATH` задают развёртывание; база по умолчанию `.data/workspace.sqlite`. Начальных паролей, пользователей и синтетических записей в поставке нет. Аккаунты создаются в «Данные и доступ».

Для публичного сервера нужны отдельный HTTPS hostname/reverse proxy, резервирование и правила хранения. Порты не изолируют cookies: не размещайте недоверенные приложения на одном hostname. Сессии HttpOnly/SameSite, пароли scrypt, CSRF/Origin и optimistic revision проверяются. Нет интерфейса отзыва сессий/сброса пароля, SSO или tenant isolation. Это не сертификат безопасности.

## Проверки и данные

`npm test`: 13 тестов предметных переходов, авторизации, HTTP, конфликтов, снимков, файлового перезапуска и пустого восстановления. [Прогон](docs/test-output.txt), [доказательства](docs/verification.json). Браузерные данные синтетические; внешний ответ/письмо не отправлялся.

JSON-копия восстанавливает рабочие записи только в пустую базу того же продукта. Аккаунты, сессии и журнал не входят в JSON; после восстановления владелец создаёт нужные аккаунты. Копия не подписана: проверяются структура и согласованность, а не подлинность автора/одобрения. Владение базой и административное восстановление — доверенная граница. Полная копия SQLite: остановить свой процесс, скопировать базу вместе с существующими WAL/SHM, проверить запуск и прежние записи. Не копировать только главный файл живой базы.

Все сотрудники видят общую рабочую область одной организации. Филиал — метка распределения, не защита данных между филиалами. Нет AI, почтового импорта, WhatsApp, live chat, внешней отправки, клиентского портала, CRM или SLA. Только ручной процесс. Предыдущие полные черновики доступны в журнале последних событий, а в самом ответе сохраняются проверенные версии, не каждый промежуточный черновик.
